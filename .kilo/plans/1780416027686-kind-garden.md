# Plan: Fix "npm run dev" stuck at compiling

## Problem
`npm run dev` hangs at the "compiling" step, and the browser shows a loading screen indefinitely.

## Root Cause Analysis

After inspecting the codebase, there are several likely culprits:

1. **`output: "standalone"` in `next.config.ts`** (`next.config.ts:5`) — This production-only mode is known to interfere with the Next.js dev server, especially in Next.js 16. It forces a standalone build pipeline even during `next dev`, which can cause the compiler to hang.

2. **Missing async exports for Server Components** (Next.js 16 requirement) — `src/app/layout.tsx` and `src/app/page.tsx` have synchronous default exports. Next.js 16's Partial Prerendering (PPR) rendering pipeline expects async Server Component exports. Synchronous exports may cause the router to never resolve the page.

3. **Persisted Zustand store with `persist` middleware** (`src/store/app-store.ts:170-402`) — The store uses `localStorage`-based persistence. When Server Components attempt to render during SSR, if any code path triggers store hydration during server render (rather than strictly on the client), it will hang because `localStorage` is unavailable on the server. The `ParticleField` client component references this store.

4. **No `middleware.ts`** — The app uses Supabase (`@supabase/ssr`) extensively. Without a middleware to refresh auth cookies, routes that call `createServerSupabaseClient()` (e.g., `src/app/api/agent/orchestrate/route.ts`) may cause the dev server to hang when it tries to resolve cookies for SSR.

## Investigation Steps (Read-Only)

1. Check if there are any compilation error logs suppressed by the dev server.
2. Verify if any `instrumentation.ts`, `instrumentations.ts`, `proxy.ts`, or `middleware.ts` files exist at the project root.
3. Inspect `node_modules/next/dist/docs/` for Next.js 16 breaking changes documentation.

## Proposed Fixes

### Fix 1: Remove `output: "standalone"` from dev configuration
- In `next.config.ts`, conditionally set `output: "standalone"` only during `next build`, not `next dev`.

### Fix 2: Make Server Component exports async
- Change `export default function Home()` in `src/app/page.tsx` to `export default async function Home()`
- Change `export default function RootLayout()` in `src/app/layout.tsx` to `export default async function RootLayout()`
- Apply the same to any other page/layout components that are Server Components.

### Fix 3: Add a Supabase `middleware.ts` (if missing)
- Create `src/middleware.ts` (with `export const config = { matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"] }`) to handle cookie refresh properly.

### Fix 4: Guard Zustand store against SSR
- Ensure `persist` middleware in `src/store/app-store.ts` does not attempt to access `localStorage` during SSR by wrapping it with a client-only check.

## Implementation Order
1. Fix next.config.ts (quick test to see if standalone is the issue)
2. Make layout/page exports async (Next.js 16 compliance)
3. Add middleware.ts (Supabase cookie handling)
4. Guard Zustand store against SSR (prevent future hangs)
